# 🧠 Kong Gateway Agent - Core Logic

This directory contains the platform-agnostic core logic for the Kong Gateway Agent. It is designed to be embedded in various platforms (VS Code, CLI, Web) by providing a unified reasoning and tool-execution engine.

## 🏗️ Architecture

The Agent core consists of three main components:

1.  **`Agent.ts`**: The main class that manages the LLM conversation loop, reasoning, and context.
2.  **`ToolManager.ts`**: Handles the discovery, registration, and execution of various tools (Docker, decK, Git, etc.).
3.  **`KongApiClient.ts`**: A technical client for interacting with the Kong Admin API.

---

## 🤖 Reasoning Engine

The agent uses a **Multi-turn Chat Completion Loop**. It is instructed to express its internal logic using `<thought>` tags before providing a user-facing response or calling a tool.

### Features:
- **Streaming Logic**: Logic inside `<thought>` can be streamed to the UI separately from the final answer.
- **Recursive Tool Use**: If a task requires multiple steps (e.g., Check Port -> Start Postgres -> Start Kong), the agent will automatically call these tools in sequence.
- **Depth Control**: A `maxToolDepth` setting prevents infinite loops in case of tool failures.

---

## ⚒️ Tool Management

Tools are defined as standard OpenAI tool definitions. The `ToolManager` maps these definitions to actual TypeScript implementations.

### Available Tool Sets:
- **Docker Lifecycle**: Start/stop/status for Postgres and Kong containers.
- **Declarative (decK)**: `validate`, `diff`, `sync`, and `reset` commands.
- **Filesystem**: Reading and writing configuration files (YAML/HTML/JS) in the storage directory.
- **GitOps**: `init`, `push`, `pull`, and `status` for syncing configuration with remote repositories.

---

## 📊 Token & Context Tracking

The `Agent` class tracks resource consumption for every interaction:
- **`inputTokens`**: Total tokens sent to the model (including system prompt).
- **`outputTokens`**: Total tokens generated by the model.
- **`contextLimit`**: Automatically detected based on the active model (e.g., 128k for GPT-4o, 1M for Gemini).
- **Percentage Tracking**: Calculates `(totalTokens / contextLimit) * 100` for UI warnings.

---

## 🛡️ Safety Protocols

The core logic enforces several safety blocks:
- **Diff Requirement**: `sync_to_kong_using_deck` is prohibited unless a `preview_sync_diff` has been performed in the same session.
- **Explicit Approval**: High-impact tools (Sync, Reset, Git Push) require a `[APPROVAL_REQUIRED]` marker to be sent to the UI.
